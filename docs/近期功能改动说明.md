## 二、一键启动 / 停止（`start.sh` / `stop.sh`）

### 背景

原脚本在 Java 17 环境、MySQL 未启动时容易失败；前台阻塞模式不便于日常开发。

### 改动

**`start.sh`**

- 自动检测并使用 **Java 21**（Homebrew 常见路径 + `/usr/libexec/java_home`）
- **MySQL 不可达时**自动切换 `spring.profiles.active=local`（H2 内存库）
- 未配置 AI 密钥时自动追加 `--lexai.ai.mode=mock`
- 默认 **后台启动**，脚本执行完毕即退出；PID 写入 `.lexai/`
- 首次运行自动 `npm install`；等待后端健康检查通过后再启前端
- 支持 `./start.sh --foreground` 前台模式（Ctrl+C 停止）

**`stop.sh`**

- 按 PID 文件 + 端口（8081 / 5173 / 5174）清理进程
- 清理 Maven / Vite 残留

### 用法

```bash
./start.sh              # 后台启动
./start.sh --foreground # 前台启动
./stop.sh               # 停止全部服务
```

## 三、AI 会话历史持久化

### 背景

法律咨询、案件分析此前为「用完即忘」，无法复盘，Dashboard 也无法展示真实 AI 活动。

### 数据模型

表名：`legal_sessions`（JPA `ddl-auto=update` 自动建表）

| 字段 | 说明 |
|------|------|
| `session_no` | 业务流水号，如 `LS-2026-001` |
| `scenario_type` | `CONSULTATION` / `CASE_ANALYSIS` |
| `title` | 输入摘要（问题 / 案情） |
| `input_payload` | 请求 JSON |
| `output_payload` | 响应 JSON |
| `confidence` | AI 置信度 |
| `trace_id` | 请求关联 ID |
| `initiator` | 发起人（默认「演示用户」） |
| `created_at` | 创建时间 |

### 写入时机

`LegalWorkspaceServiceImpl` 在以下接口 **成功返回后** 自动落库：

- `POST /api/legal/consultation`
- `POST /api/legal/case-analysis`

持久化失败仅打日志，**不影响**主流程响应。

### 新增 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/legal/sessions?type=CONSULTATION\|CASE_ANALYSIS&page=&size=` | 分页列表 |
| GET | `/api/legal/sessions?type=...&keyword=xxx` | 按标题 / 会话号模糊搜索 |
| GET | `/api/legal/sessions/recent?limit=5` | 最近 N 条（Dashboard 用） |
| GET | `/api/legal/sessions/{id}` | 详情（含完整 input/output JSON） |

### 前端

- 组件：`frontend/src/shared/ui/LegalSessionHistoryPanel.vue`
- 挂载页：法律咨询、案件分析左侧栏
- 点击历史项可 **恢复** 表单输入与 AI 结果
- 提交成功后自动刷新列表

## 四、工作台数据可视化

### 背景

合同统计接口 `/api/contracts/statistics` 此前仅在合同台账页使用，Dashboard 仍为静态骨架。

### 改动

**`DashboardView.vue`**

- 接入 `fetchContractStatistics()`，展示真实合同总数与统计卡片
- 新增 `DashboardCharts.vue`（依赖 **ECharts**）：
  - 合同状态分布（环形图）
  - 合同类型分布（柱状图）
  - 近 6 个月新建趋势（折线图）
- 统计卡片改为展示「法律咨询历史」「案件分析历史」会话数

**系统运行状态**

- 由 `GET /api/system/health` 动态展示：
  - `aiMode`（mock / tencent）
  - `database`（MySQL / H2 内存库）
  - 知识库文档数、chunk 数
  - 咨询 / 分析会话总数

## 五、Dashboard「最近 AI 活动」

### 背景

原「最近活动」来自待办任务列表，与 AI 工具链无关，且多为 seed 演示数据。

### 改动

- 卡片标题改为 **「最近 AI 活动」**
- 数据来源：`GET /api/legal/sessions/recent?limit=5`
- 展示咨询 / 分析类型、标题、相对时间
- 点击条目跳转对应页面（`consultation` / `caseAnalysis`）

## 六、咨询 / 分析历史搜索

### 后端

`LegalSessionRepository.searchByScenarioTypeAndKeyword`：对 `title`、`session_no` 做 `LIKE` 模糊匹配（忽略大小写）。

### 前端

历史侧栏增加搜索框，调用：

```
GET /api/legal/sessions?type=CONSULTATION&keyword=工资&page=0&size=10
```

## 七、扩展的系统健康接口

`GET /api/system/health` 响应由 `{ "status": "UP" }` 扩展为：

```json
{
  "status": "UP",
  "aiMode": "tencent",
  "database": "MySQL",
  "knowledgeDocumentCount": 8,
  "knowledgeChunkCount": 42,
  "consultationSessionCount": 12,
  "caseAnalysisSessionCount": 3
}
```

## 八、仍为演示 / 模拟的部分（答辩时注意）

| 项目 | 说明 |
|------|------|
| AI Mock 模式 | `lexai.ai.mode=mock` 或无密钥时，走规则模板 |
| AI 兜底 | tencent 模式下 API 失败时仍可能回退规则化输出 |
| `data.sql` seed | 8 份合同 + 4 条待办为「演示数据导入」 |
| 用户体系 | 无登录，发起人固定「演示用户」 |
| 前端装饰文案 | Hero 技术标签、AiThinkingPanel 步骤等为固定 UI 文案 |
| 知识库 | `docs/knowledge-base/` 8 份静态 txt，检索真实但内容非实时法规库 |

配置真实密钥后，AI 主链路为 **腾讯混元 + 得理 + 本地 RAG**；详见 `backend/.env.example` 与 `docs/AI接口密钥配置与调用操作指南（成员通用）.md`。
