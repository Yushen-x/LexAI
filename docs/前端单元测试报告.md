# 前端单元测试报告

本文档记录 LexAI 前端从零搭建的单元测试体系、覆盖范围、运行方式与最近一次执行结果，
便于评审与后续维护。

## 一、背景与目标

前端此前没有任何自动化测试，核心的 API 客户端（响应信封拆解、在途去重、错误码映射）、
各业务接口的参数清洗逻辑以及全局 toast 工具均依赖人工点测验证。本次工作的目标是：

- 引入轻量测试框架，建立可持续运行的测试基线；
- 优先覆盖**有真实逻辑分支**的代码（请求去重、参数过滤、状态码映射、DOM 生命周期），
  而非无意义的 getter/常量堆砌；
- 不改动任何业务代码，纯增量、零回归风险。

## 二、技术选型

| 组件 | 选型 | 说明 |
| --- | --- | --- |
| 测试框架 | Vitest 2.1 | 与 Vite 同构，复用 `@` 别名与构建配置，启动快 |
| DOM 环境 | jsdom 25 | 为 toast 等依赖 `document` 的工具提供浏览器环境 |
| 组件测试库 | @vue/test-utils 2.4 | 预置，供后续组件测试使用 |

配置文件 `frontend/vitest.config.ts`：复用 `@ → src` 别名，`environment: 'jsdom'`，
开启 `globals` 与 `clearMocks`（每个用例自动重置 mock，避免相互污染）。

`package.json` 新增脚本：

- `npm test` —— 单次运行全部测试（`vitest run`）；
- `npm run test:watch` —— 监听模式，开发时实时反馈。

## 三、测试覆盖范围

共 6 个测试文件、41 个用例，分布如下：

| 测试文件 | 被测对象 | 用例数 | 关键覆盖点 |
| --- | --- | --- | --- |
| `src/shared/api/http.spec.ts` | API 客户端与响应拦截器 | 17 | 信封拆解（get/post/put/del）、GET 在途去重、业务码非 SUCCESS 拒绝、HTTP 401/403/404/500/503 状态映射、400/422 优先取后端 message、无响应/请求构造异常兜底 |
| `src/shared/api/contracts.spec.ts` | 合同接口 | 7 | 空筛选字段过滤为 undefined、分页默认值、各子资源 url 拼装、payload 透传 |
| `src/shared/api/legal.spec.ts` | 法律会话接口 | 5 | 分页默认值、关键字 trim 与纯空白回落、recent 默认 limit、详情/咨询路径 |
| `src/shared/api/tasks.spec.ts` | 任务接口 | 4 | 有无状态的查询参数构造、详情与状态子资源路径 |
| `src/shared/ui/toast.spec.ts` | 全局 toast 工具 | 5 | 空消息忽略、容器挂载与复用、超时自动移除、点击关闭、容器清空回收 |
| `src/shared/constants/contractTypes.spec.ts` | 合同类型常量 | 3 | 选项非空、value 唯一性、派生数组与选项一致 |

### 重点说明

- **在途去重（http.spec.ts）**：通过受控 Promise 模拟未完成的请求，验证并发相同
  `url + params` 时底层 `axios.get` 只触发一次，且请求完成后从在途池移除、后续相同
  请求会重新发起；不同 params 不去重。
- **错误码映射（http.spec.ts）**：直接取出拦截器注册时传入的 `onFulfilled / onRejected`
  处理函数进行断言，使用 `it.each` 参数化覆盖五类状态码，并验证均触发 `toast` 错误提示。
- **toast 生命周期（toast.spec.ts）**：使用 `vi.useFakeTimers()` 推进展示时长与淡出动画，
  验证元素与容器在适当时机被回收，杜绝内存/DOM 泄漏。

测试通过 mock `axios`、`@/shared/api/http` 与 `@/shared/ui/toast` 隔离真实网络与全局副作用，
保证用例稳定、可重复。

## 四、运行方式

```bash
cd frontend
npm install   # 首次需安装 vitest / jsdom 等开发依赖
npm test      # 运行全部单元测试
```
