# 性能优化与测试说明

本文档汇总 LexAI 在「系统优化」方向上的改造点、设计取舍及对应测试，便于评审与后续维护。

## 一、性能与可观测性优化

### 1. 业务流水号统一（重构）

- **问题**：`ContractService` 与 `TaskService` 各自维护了几乎相同的 `nextSequence` 解析与
  号段格式化逻辑，规则容易在两处漂移。
- **改造**：抽取无状态工具 `application/service/support/SequenceGenerator`，统一
  「前缀拼接 → 解析当前最大号 → 自增 → 补零格式化」四步，两个 Service 复用。
- **取舍**：本次仅做重构去重，保留原有创建锁，行为不变；并发下的号码唯一性仍由
  事务/锁与数据库唯一约束共同保证。

### 2. 合同统计缓存（Caffeine + Spring Cache）

- **问题**：统计接口读多写少，且每次需多张/多次聚合查询。
- **改造**：`CacheConfig` 启用 Caffeine（`expireAfterWrite=60s`，`maximumSize=500`）；
  `ContractStatisticsService` 的 summary / 状态分布 / 类型分布 / 月度趋势四个口径加
  `@Cacheable`；合同写操作（增改删审）通过组合注解 `@EvictContractStatsCaches`
  主动清空统计缓存。
- **取舍**：短 TTL 兜底 + 写操作主动失效，把数据陈旧窗口控制在秒级。注意 `summary()`
  内部对其它方法属自调用、不经缓存代理，其整体结果由 `summary` 自身缓存兜底。

### 3. 知识库检索倒排预筛 + 查询缓存

- **问题**：`LocalKnowledgeSearchClient` 每次查询对全部 chunk 计算余弦相似度，
  知识库变大后线性扫描成本高。
- **改造**：利用「查询与 chunk 无共享词项则余弦必为 0」的性质（原实现也会
  `score <= 0` 跳过），在加载索引时构建 **词项 → chunk 下标** 倒排索引，检索仅对与
  查询词项有交集的候选 chunk 计算相似度；并对 `(query, topK)` 增加有界 LRU 结果缓存，
  索引重建时自动失效。
- **取舍**：该优化**不改变返回结果**，仅减少计算量；倒排索引仅存内存、不落盘，避免
  改动既有索引文件格式。

### 4. 数据库索引

`ContractEntity` 针对统计/列表的访问路径补充复合索引：

| 索引 | 列 | 服务的查询 |
| --- | --- | --- |
| `idx_contract_deleted_status` | `deleted, status` | 状态分布、按状态过滤 |
| `idx_contract_deleted_type` | `deleted, contract_type` | 类型分布 |
| `idx_contract_deleted_created_at` | `deleted, created_at` | 月度趋势（范围 + 分组）|

### 5. 请求关联 ID 与失败日志

- `RequestCorrelationFilter` 为每个请求绑定 `traceId`（透传 `X-Request-Id` 或生成），
  写入 MDC 并回写响应头；日志 pattern 追加 `[traceId]`，串联一次请求内的多步调用。
- `LocalKnowledgeSearchClient` 的兜底 `catch` 由静默吞异常改为 `warn` 日志（仍降级返回
  空结果，不中断主流程），便于排查检索故障。

### 6. 前端

- 路由保持组件级懒加载（`() => import(...)`）。
- `vite` 配置 `manualChunks`，将 `vue/vue-router/pinia`、`axios`、图标库拆为独立 vendor
  chunk，提升浏览器长缓存命中。
- `shared/api/http.ts` 新增轻量 `api` 客户端：统一拆解 `{code,message,data}` 信封，
  消除各模块重复的 `.data.data` 样板；GET 默认在途去重，并发相同请求复用同一 Promise
  （写操作不去重，保留用户的重复提交语义）。

## 二、测试

### 后端

JUnit 5 + Mockito，覆盖单元与集成两层：

| 测试类 | 关注点 |
| --- | --- |
| `SequenceGeneratorTest` | 号段解析、跨年、脏数据、补零、溢出 |
| `ContractStatusTest` | 合同状态机合法/非法流转、终态、自转移 |
| `ContractServiceTest` | 状态校验、审查 JSON 落库、软删除、风险截断 |
| `TaskServiceTest` | 待办去重、决策→状态联动闭环 |
| `LocalKnowledgeSearchClientTest` | 相关性排序、topK、无关/空查询、缓存幂等 |
| `RequestCorrelationFilterTest` | traceId 透传/生成/清理/截断 |
| `ContractStatisticsCacheIntegrationTest` | 统计缓存命中与写后失效 |

运行与覆盖率：

```bash
cd backend
mvn test
# 覆盖率报告：target/site/jacoco/index.html
```

### 前端

```bash
cd frontend
npm run build   # vue-tsc 类型检查 + vite 构建
```

## 三、可回退性

所有改造均在 `feature/system-optimization` 分支以独立提交推进，未改写历史、未强制推送；
`main` 始终可回退到改造前版本。
